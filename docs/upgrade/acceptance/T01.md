# T01 acceptance: strict configuration and multidimensional status

**Status: ACCEPTED**

T01 adds [contracts.py](../../../src/GemAgents/contracts.py), the JSON schema, and
regression coverage. Existing reconstruction behavior and scientific thresholds
remain unchanged. User configuration is validated before pipeline work starts;
internal retry directions are passed through `ReconstructionContext`, so the public
config cannot silently enable internal controls.

Configuration validation now rejects unknown fields, duplicate JSON/YAML keys,
YAML merge collisions, string booleans, nonfinite numbers, invalid integer budgets,
negative growth, contradictory reference settings and invalid presets. Current
native and v37 JSON configs load and validate against the schema. YAML state loading
uses the same duplicate-key rejection and the duplicate `boundaries` block was
removed while retaining the first block's exclusions and public reuse policy.

Quality reports retain legacy `status` and add `execution_status`, `model_status`,
`validation_status`, `benchmark_eligibility`, `repair_search_status` and
`final_audit_status`. Each required applicable check has status, scope, reason and
applicability. Solver/numerical/timeout/configuration failures and unresolved
checks cannot count as complete; repair budget exhaustion is retained alongside
final audit status. The existing pipeline still writes all legacy artifacts.
