# T02 acceptance: solver outcomes and candidate fallback

**Status: ACCEPTED**

`SolveResult` keeps backend status, exception type, incumbent state, objective,
residual, elapsed time, timeout and a unique attempt ID. The native gap fill loop
opens a lower evidence tier only after an explicit `infeasible` result and only
when policy authorizes that tier. Timeout, unbounded, numerical, import, file and
program errors stop without expanding the candidate pool.

The solve event artifact records each tier, candidate counts, transition reason
and attempt ID. An incumbent from a nonoptimal solve is never promoted to an
accepted reconstruction.

Evidence:

- `tests/test_gapfill_failure_modes.py` injects typed and backend failures into
  the native builder, including misleading exception text.
- T02 regression command: **102 passed, 0 failed**. JUnit and stdout are under
  `artifacts/audit/T02/`.
- Full repository suite after T02–T05: **201 passed, 0 failed**; repository Ruff
  check and `git diff --check` passed.

Rollback removes the solver adapter and guarded loop while retaining failed run
artifacts. Returning to exception driven candidate expansion is forbidden.
